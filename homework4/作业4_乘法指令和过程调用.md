# 作业4：乘法指令和过程调用

## 一、实验内容

1. 用双重循环和 `MUL` 输出倒序的三角形九九乘法表，用 `CALL`、`RET` 实现过程调用。
2. 逐项检查完整的 9×9 字节数组，对比各项与行号、列号的乘积，输出错误项坐标。
3. 用 C 实现两项功能，观察并注释反汇编，比较纠错程序中的全局数组和局部数组。

程序在 DOSBox-X 中运行。汇编使用 MASM 5.00 和 Microsoft LINK 3.60，C 使用 Open Watcom C16，目标为 8086、16 位 DOS；调试使用 FreeDOS DEBUG。

## 二、输出九九乘法表

[H4TAB.ASM](src/H4TAB.ASM) 的外循环让行号 `x` 从 9 递减到 1，内循环让列号 `y` 从 1 递增到 `x`。第 `x` 行有 `x` 项，共输出 45 项。每项之间用空格对齐，单个显示列宽为 8 个字符，行尾直接换行。

主程序以 BX 保存 `x`、SI 保存 `y`、CX 保存本行剩余次数。每次调用 `PRINT_TERM`，再推进列号。过程内把 `y` 放入 AL、`x` 放在 BL，执行 `MUL BL`，无符号乘积保存在 AX。因 `1 ≤ x,y ≤ 9`，乘积最多为 81。

```asm
COL_LOOP:
    CALL PRINT_TERM
TERM_RETURN:
    INC SI
    LOOP COL_LOOP
```

`PRINT_TERM` 先压栈保存 AX、CX、DX，然后输出 `x*y=积`。如果该项后面还有一列，过程借用 CX 循环输出两个或三个空格，返回前用 `POP CX` 恢复调用者的计数。公共子程序 `PRINT_DEC` 也会借用 BX、CX 作除数和计数，按逆序恢复保存的寄存器。它反复除以 10，将余数压栈，再从高位到低位弹出、加字符 `'0'`，最后由 `INT 21H/AH=02H` 输出。公共子程序见 [H4IO.INC](src/H4IO.INC)。

### 调试过程调用

第一次调用输出 `9*1=9`。[DEBUG 记录](logs/H4TAB.DBG) 显示：

| 停止位置 | BX | CX | SI | SP | 说明 |
| --- | --- | --- | --- | --- | --- |
| `0015` | `0009` | `0009` | `0001` | `0100` | 执行 `CALL` 前 |
| `0026` | `0009` | `0009` | `0001` | `00FE` | 到达过程入口，返回地址已压栈 |
| `0052` | `0009` | `0003` | `0001` | `00F8` | 保存三个字后，CX 已改为补空格次数 |
| `0018` | `0009` | `0009` | `0001` | `0100` | `RET` 回到 `CALL` 的下一条指令 |

近调用 `CALL` 压入下一条指令的 IP，`RET` 弹出它；过程中的 `PUSH`、`POP` 负责保存和恢复寄存器。回到 `0018` 时，主程序可以继续使用原来的 BX、SI 和 CX。

汇编与 C 版的输出逐字节一致：[汇编乘法表](output/H4TAB.txt) · [C 乘法表](output/H4CTAB.txt)。

## 三、检查乘法表

[H4CHK.ASM](src/H4CHK.ASM) 按行存放 81 个字节。外循环与内循环都遍历 1～9。对外显示的行列号从 1 起算；数据下标从 0 起算，第 `x` 行第 `y` 列的下标为 `(x-1)×9+(y-1)`。

程序初始化 DS，令 DI 从 0 开始，每检查一项就执行 `INC DI`。因此 `TABLE_DATA[DI]` 等价于按上述公式读取对应单元格，寻址使用 `DS:[OFFSET TABLE_DATA+DI]`。`CHECK_CELL` 每次重新用 `MUL BL` 计算 `x*y`，再执行 `CMP AL,TABLE_DATA[DI]`。相等则返回，不相等则输出行号和列号。乘积不超过 81，因此可直接比较 AL 和单字节表项。

在第一次错误项 `(1,1)` 的调试中，调用前 `BX=0001`、`CX=0009`、`SI=0001`、`DI=0000`、`SP=0100`。进入 `CHECK_CELL` 调用的 `PRINT_DEC` 后，`BX=000A`、`CX=0001`，分别用于十进制除法和字符计数。返回到 `001B` 时，四个循环相关寄存器与 SP 均恢复为调用前的值，随后主程序才推进 DI 和 SI。[DEBUG 记录](logs/H4CHK.DBG)

| 错误坐标 `(x,y)` | 数据下标 | 表内值 | 正确值 |
| --- | --- | --- | --- |
| `(1,1)` | 0 | 7 | 1 |
| `(2,3)` | 11 | 7 | 6 |
| `(4,5)` | 31 | 7 | 20 |
| `(6,6)` | 50 | 7 | 36 |
| `(8,8)` | 70 | 7 | 64 |

```text
x y
1 1   error
2 3   error
4 5   error
6 6   error
8 8   error

accomplish!
```

程序报告位置，保留原数组内容。全局、局部两种 C 纠错程序与汇编版的结果一致：[汇编](output/H4CHK.txt) · [C 全局](output/H4CGLOB.txt) · [C 局部](output/H4CLOC.txt)。

## 四、C 实现与反汇编对比

乘法表的 C 版 [H4TAB.C](src/H4TAB.C) 以两层 `for` 循环控制行列。实际反汇编中的 `MUL WORD PTR [BP-04]` 用 AX 中的行号乘以栈中的列号，积的低 16 位保存到局部变量 `product`，随后调用 `printf` 输出。

纠错的两个 C 版本共用 [H4CHK.C](src/H4CHK.C) 中的扫描算法和初始化数据。默认把 `unsigned char table[9][9]` 定义为全局对象；编译时定义 `LOCAL_TABLE`，则在 `main` 内建立局部数组。两者的数组容量都是 81 字节。

| 比较项 | 全局数组 | 局部数组 |
| --- | --- | --- |
| 运行时存储 | 已初始化的静态数据 | `main` 的栈帧 |
| `main` 分配的局部空间 | `06H` 字节 | `58H` 字节，含 81 字节数组 |
| 初始化 | 程序装载时已有数据 | 进入 `main` 后从模板复制 81 字节 |
| 查表指令 | `MOV AL,[BX+00B7]` | `MOV AL,[BP+SI-59]` |
| 默认段寄存器 | DS | SS |

局部版通过 `REP MOVSW` 复制 40 个字，再用 `MOVSB` 复制最后一个字节。两种查表指令都将读到的 `unsigned char` 零扩展后，再与 `MUL` 得到的正确乘积比较。各指令的实际机器码和解释见 [C 反汇编逐行注释](C反汇编_逐行注释.md)。

## 五、编译与验证

在 DOSBox 的 `src` 目录执行 `H4BUILD`，可生成 `H4TAB.EXE` 和 `H4CHK.EXE`。也可逐个运行 `masm H4TAB;`、`link H4TAB;`，再对 `H4CHK` 重复相同操作。两份 ASM 都要与 `H4IO.INC` 放在同一目录。

C 程序在 Windows 中用 Open Watcom 构建。设置 WATCOM、INCLUDE 和 PATH 后，在源码目录执行：

```text
wcl -0 -ms -bt=dos -l=dos -od -d2 -s -w=4 -we -fe=H4CTAB.EXE -fo=H4CTAB.OBJ -fm=H4CTAB.MAP H4TAB.C
wcl -0 -ms -bt=dos -l=dos -od -d2 -s -w=4 -we -fe=H4CGLOB.EXE -fo=H4CGLOB.OBJ -fm=H4CGLOB.MAP H4CHK.C
wcl -0 -ms -bt=dos -l=dos -od -d2 -s -w=4 -we -dLOCAL_TABLE=1 -fe=H4CLOC.EXE -fo=H4CLOC.OBJ -fm=H4CLOC.MAP H4CHK.C
```

五份 EXE 均在 DOSBox 中运行验证，原始输出和调试记录分别位于 [output](output/) 和 [logs](logs/)。针对三种纠错实现，在临时 EXE 副本中分别换入全正确表，再把每个位置单独改成 0。三个无错误用例均未报错；`3×81=243` 个逐格用例均只报出改动的那一格。加上编译、输出和调试检查，共 **271/271 项通过**。[验证结果](验证结果.json) · [逐格记录](logs/逐格测试.csv)
