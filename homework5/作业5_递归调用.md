# 作业5：递归调用

## 一、实验任务

从键盘读入 `1 ≤ n ≤ 100`，按 `F(0)=0`、`F(1)=1`、`F(n)=F(n-1)+F(n-2)` 递归计算第 `n` 项。用 DEBUG 观察 `CALL`、`RET` 前后的栈指针，并根据递归深度和每层栈开销确定栈容量。

| 实现 | 源码 | DOS 程序 |
| --- | --- | --- |
| 8086 汇编 | [H5FIB.ASM](src/H5FIB.ASM) | [H5FIB.EXE](bin/H5FIB.EXE) |
| C | [H5CFIB.C](src/H5CFIB.C) | [H5CFIB.EXE](bin/H5CFIB.EXE) |

汇编使用 MASM 5.00、Microsoft LINK 3.60；C 使用 Open Watcom C16。两个版本均以 8086、16 位 DOS 为目标，在 DOSBox-X 中运行，用 FreeDOS DEBUG 跟踪。

## 二、递归与数值表示

`F(100)=354224848179261915075`，超过无符号 64 位整数上限 `18446744073709551615`。每项使用 21 个字节，每字节存一个 `0～9` 的十进制数位，个位放在数组开头。求和从个位开始，当前位与进位的和最大为 19；若和达到 10，就减 10 并向下一位进 1。输出时逆向扫描，跳过前导零，再将数位加上字符 `'0'`。

`cache` 共有 101 项，占 `101×21=2121` 字节；`ready` 另用 101 字节记录各项是否已算好。启动时只初始化 `F(0)` 和 `F(1)`。`FIB` 先查 `ready[n]`，命中时返回该项的地址；未命中时分别递归调用 `FIB(n-1)` 和 `FIB(n-2)`，将两个结果相加并缓存。缓存仅保存已算出的值，递推依然由两条递归 `CALL` 完成。每个 `n≥2` 只做一次 21 位加法，时间复杂度为 `O(n×21)`，递归深度为 `O(n)`。

汇编输入使用 `INT 21H/AH=0AH`，按十进制累加输入字符。空行、负号、非数字、超出三位或不在 1～100 的数值会触发重新输入；三位以内允许前导零。C 版使用 `getchar` 读取并检查同一输入范围。

## 三、寄存器分工与过程调用

| 寄存器 | `FIB` 中的用途 |
| --- | --- |
| AX | 接收参数 `n`，计算 `n×21`；在加法中用 AL 保存当前数位和 |
| BX | 保存本层 `n`；逐位加法期间指向第一个操作数 |
| DI | 指向本层结果区，逐位写入时移动 |
| SI | 递归返回值，即 `DS:SI` 指向结果；加法时指向第二个操作数 |
| CX | 数位循环计数；也短暂保存当前层的 `n` |
| DL | 当前十进制进位，取值为 0 或 1 |
| SP | 指向返回地址、保存的寄存器和临时量 |

`FIB` 入口依次保存 BX、DI、CX、DX，返回前逆序恢复。第一个子调用返回后，将它的 SI 压栈；第二个子调用返回后，弹出原指针以参与加法。AX、SI 和标志位允许被过程改写，其中 SI 专门用于传回结果地址。

```asm
    MOV AX,BX
    DEC AX
RECURSE_LEFT:
    CALL FIB
    PUSH SI
    MOV AX,BX
    SUB AX,2
RECURSE_RIGHT:
    CALL FIB
```

## 四、DEBUG 单步调试过程

使用 [TRACE5.IN](logs/TRACE5.IN) 可以复现 `F(5)`：在 DOS 提示符执行 `debug H5FIB.EXE < TRACE5.IN`，其中命令文件应与 EXE 位于同一目录。脚本先单步执行前两条指令以初始化 DS，手工设 `AX=0005`、`IP=0058`，再用 `g` 到各个调用或返回点；每次先用 `r` 记录寄存器，再用 `t` 单步执行该条 `CALL` 或 `RET`。键盘输入另由运行用例验证。

以下为 [完整 DEBUG 日志](logs/TRACE5.DBG) 中的实际值，偏移及 SP 均为十六进制。深度含当前过程帧。

| 步 | 指令 | n | 深度 | IP 前 → 后 | SP 前 → 后 |
| --- | --- | ---: | ---: | --- | --- |
| 1 | CALL | 5 | 1 | `0058 → 007A` | `1000 → 0FFE` |
| 2 | CALL | 4 | 2 | `0095 → 007A` | `0FF6 → 0FF4` |
| 3 | CALL | 3 | 3 | `0095 → 007A` | `0FEC → 0FEA` |
| 4 | CALL | 2 | 4 | `0095 → 007A` | `0FE2 → 0FE0` |
| 5 | CALL | 1 | 5 | `0095 → 007A` | `0FD8 → 0FD6` |
| 6 | RET | 1 | 5 | `00D0 → 0098` | `0FD6 → 0FD8` |
| 7 | CALL | 0 | 5 | `009E → 007A` | `0FD6 → 0FD4` |
| 8 | RET | 0 | 5 | `00D0 → 00A1` | `0FD4 → 0FD6` |
| 9 | RET | 2 | 4 | `00D0 → 0098` | `0FE0 → 0FE2` |
| 10 | CALL | 1 | 4 | `009E → 007A` | `0FE0 → 0FDE` |
| 11 | RET | 1 | 4 | `00D0 → 00A1` | `0FDE → 0FE0` |
| 12 | RET | 3 | 3 | `00D0 → 0098` | `0FEA → 0FEC` |
| 13 | CALL | 2 | 3 | `009E → 007A` | `0FEA → 0FE8` |
| 14 | RET | 2 | 3 | `00D0 → 00A1` | `0FE8 → 0FEA` |
| 15 | RET | 4 | 2 | `00D0 → 0098` | `0FF4 → 0FF6` |
| 16 | CALL | 3 | 2 | `009E → 007A` | `0FF4 → 0FF2` |
| 17 | RET | 3 | 2 | `00D0 → 00A1` | `0FF2 → 0FF4` |
| 18 | RET | 5 | 1 | `00D0 → 005B` | `0FFE → 1000` |

近 `CALL` 压入 2 字节返回 IP，`RET` 弹出 2 字节。第 6 步返回到第一条递归 `CALL` 的下一条指令 `0098`，该处执行 `PUSH SI`，所以第 7 步的 SP 又比第 6 步返回后少了 2。第 13 和 16 步命中缓存，进入后没有继续递归。最后返回主程序时 SP 恢复 `1000H`，继续运行后输出 `5`。

## 五、栈容量计算

**汇编版。** `.STACK 1000H` 预留 4096 字节，EXE 装载器按头部设置 SS:SP，实测初始 SP 为 `1000H`。每个 `FIB` 活动帧有 2 字节返回 IP 和 8 字节寄存器保存，共 10 字节。计算 `F(100)` 时，先沿左支路到 `F(2)`；完成 `F(1)` 后，`F(2)` 多压入 2 字节指针，再调用 `F(0)`。此时 100 层同时存在，故峰值为 `100×10+2=1002` 字节。祖先仍在等待各自的左支路，尚未压入临时指针；其余右支路命中缓存，活动层数更少。

[最大输入跟踪](logs/MAX100.DBG) 中，从 `SP=1000H` 出发，到 `F(0)` 完成四个 `PUSH` 时为 `0C16H`，差值正好是 1002 字节。递归过程内不调用 DOS 中断；输入输出在递归外执行。4096 字节相对递归峰值留出 3094 字节，不应把恰好 1002 字节当作整个程序的栈配置。

**C 版。** 编译时用 `-k4096`。当前 `fib_` 每层包含 2 字节返回地址、六个字的寄存器保存、`14H` 字节局部空间，共 34 字节，100 层需要 3400 字节。运行库初始化之后，在 `main` 调用 `fib_` 前的 SP 为 `1AD8H`；最深处为 `0D90H`，差值为 3400 字节，返回后恢复为 `1AD8H`。链接映射中的栈底相对 DGROUP 为 `0AF0H`，最深处仍高于栈底 672 字节。这里的 SP 是段内偏移，不能直接当作已分配的栈容量。[C 栈跟踪](logs/CMAX100.DBG) · [链接映射](logs/H5CFIB.MAP)

## 六、C 反汇编与验证

C 版的 `fib_` 在 `CS:0010`，在 `0040`、`004C` 两处真正调用自身；AX 传入下标，返回时 AX 保存数位数组的近指针。`[BP-0A]` 和 `[BP-08]` 保存左右两个子调用返回的结果数组指针；`[BP-02]` 用于保存进位。`main_` 在 `CS:0212`，完成输入、调用、输出和返回。详见 [逐行注释](C反汇编_逐行注释.md) 及 [DEBUG 原始反汇编](logs/CDIS.DBG)。

| n | 两个版本均输出 |
| ---: | ---: |
| 1 | `1` |
| 5 | `5` |
| 47 | `2971215073` |
| 94 | `19740274219868223167` |
| 100 | `354224848179261915075` |

两种实现分别验证了 100 个正常输入及 11 个前导零或非法输入重试用例，共 222 个输入用例；另外核对了 18 次单步、最大输入的栈使用、编译及反汇编。总计 **255/255 项通过**。[验证结果](验证结果.json) · [逐用例记录](logs/输入测试.csv)

## 八、调试笔记

我先用 `n=5` 跟踪递归，没有直接从 100 开始逐步看。这个输入能走到 `F(1)` 和 `F(0)`，也能看到返回后再调用另一个分支的过程。第一条 `CALL` 执行后，SP 从 `1000H` 降到 `0FFEH`；后面每层还要保存四个寄存器。我沿着调用往下记录，再对照返回地址看程序回到哪一层，最后回到主程序时 SP 恢复到 `1000H`。[单步记录](logs/TRACE5.DBG)

测最大栈用量时，我第一次在 `F(0)` 的 `RET` 前读到 `SP=0C1EH`，用初始值减下来是 994 字节，和按指令算的 1002 差了 8。这让我重新检查了断点的位置：到 `RET` 前，四条 `POP` 已经执行完了，正好释放了 8 字节。把观察点移到入口四条 `PUSH` 刚结束的 `007EH`，SP 是 `0C16H`，差值才是 1002。问题出在我选的观察时刻，不能把返回前的栈占用当作峰值。[栈用量记录](logs/MAX100.DBG)

我还核对了多出来的 2 字节从哪里来。`F(2)` 算完左边的 `F(1)` 后，会先把结果指针压栈，再调用 `F(0)`，所以同样的递归深度也可能有不同的 SP。数值部分则重点看了较大的输入：`F(94)` 已经超过无符号 64 位范围，`F(100)` 有 21 位，不能只用小输入验证。两个版本的全部 1～100 输入及重试记录都核对后，我才确认数位进位和逆序输出能覆盖题目的上限。[输入测试记录](logs/输入测试.csv)

## 九、实验心得

这次我对递归的理解比写出那条公式具体了很多。每一层返回后还要继续做自己的事，所以当前参数、返回地址和需要留下的结果都必须有地方保存。尤其是第一个子调用的结果，第二次调用会继续使用寄存器，不能想当然地认为它还留在原处。顺着 `F(5)` 的调用和返回看一遍，我才更容易把源码中的两条 `CALL` 和栈里的内容对应起来。

我也意识到，这道题要同时考虑计算次数、数值范围和栈空间。缓存避免重复计算，21 位数位数组负责容纳大数，栈负责保存仍未返回的调用，这三件事各有用途。测出 1002 字节以后，也不能就把整个程序的栈设成 1002 字节，输入输出同样需要栈。C 版的递归栈开销又比汇编版大，让我看到同一个算法经过不同实现后，实际资源占用并不会自动相同。以后检查递归程序，我会把最大输入和最深处的现场都看过，再判断空间是否够用。
