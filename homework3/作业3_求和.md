# 作业3：求和

## 一、实验目的

1. 计算 `1+2+…+100`，将结果 `5050` 以十进制形式输出到屏幕。
2. 分别使用寄存器、数据段和栈保存求和阶段的累计值，比较操作方式。
3. 读取1～100之间的整数 `n`，计算并输出 `1+2+…+n`。
4. 用 C 语言实现固定范围求和，查看并注释编译后的反汇编。

## 三、结果的表示范围

理论结果可用于核对程序输出：

```text
1+2+…+100 = 100×101÷2 = 5050
5050 = 13BAH
```

8位无符号数只能表示0～255，无法容纳5050。程序使用16位寄存器或一个字 `DW` 保存累计值，16位无符号数的范围为0～65535。对于任意 `n=1～100`，最大和都是5050，因此累加过程不会溢出。

内存以低字节在前保存字数值，`13BAH` 在内存中的两个字节依次为 `BA 13`。数值5050与字符序列 `'5'、'0'、'5'、'0'` 的表示不同；字符的 ASCII 码为 `35H、30H、35H、30H`，输出前需要数位转换。

## 四、固定范围求和与三种保存位置

### 1. 寄存器保存累计值

AX 保存累计和，BX 保存当前加数，CX 保存剩余循环次数。

```asm
XOR AX,AX
MOV BX,1
MOV CX,100
SUM_LOOP:
    ADD AX,BX
    INC BX
    LOOP SUM_LOOP
SUM_DONE:
    CALL PRINT_DEC
    CALL NEWLINE
```

第1轮加1，第100轮加100。循环结束时 `AX=13BAH`、`BX=0065H`、`CX=0000H`，其中 `0065H` 是十进制101。`PRINT_DEC` 使用 AX 作为参数，并通过 PUSH/POP 恢复调用前的寄存器内容。

### 2. 数据段保存累计值

```asm
.DATA
    RESULT DW 0
.CODE
    MOV AX,@DATA
    MOV DS,AX
    MOV RESULT,0
    MOV BX,1
    MOV CX,100
SUM_LOOP:
    ADD RESULT,BX
    INC BX
    LOOP SUM_LOOP
SUM_DONE:
    MOV AX,RESULT
    CALL PRINT_DEC
```

每轮直接更新内存变量 RESULT。输出前再把 RESULT 读入 AX。本次链接后 RESULT 的组内偏移为 `000AH`，因此 DEBUG 查看位置为 `DS:000A`，其中保存 `BA 13`。

源码中 RESULT 是数据段的第一个变量；它在链接后的 DGROUP 中仍可能带有段对齐形成的偏移。本次 MAP 中 `_DATA` 起始位置为 `005AH`，DGROUP 基址为 `0050H`，所以组内偏移是 `005AH-0050H=000AH`。

### 3. 栈保存累计值

```asm
PUSH BP
MOV BP,SP
SUB SP,2
MOV WORD PTR [BP-2],0
MOV BX,1
MOV CX,100
SUM_LOOP:
    ADD WORD PTR [BP-2],BX
    INC BX
    LOOP SUM_LOOP
SUM_DONE:
    MOV AX,[BP-2]
    CALL PRINT_DEC
    CALL NEWLINE
    MOV SP,BP
    POP BP
```

`PUSH BP` 保存旧 BP，`MOV BP,SP` 建立栈帧，`SUB SP,2` 分配一个字的局部空间。含 BP 的该内存寻址默认使用 SS，所以 `[BP-2]` 指向栈段中的局部变量。

初始 `SP=0100H`；保存 BP 后，`BP=00FEH`；分配局部空间后，`SP=00FCH`。求和结束时，结果位于 `SS:00FC`，内容为 `13BAH`。输出子程序继续向更低的地址使用栈，返回后恢复原来的局部变量位置；最后 `MOV SP,BP`、`POP BP` 释放局部空间并恢复 BP。

### 4. DEBUG 对比

| 版本 | 求和完成时的观察位置 | 结果 |

| 寄存器版 | `AX` | `13BAH` |

| 栈版 | `SS:SP`，此时等于 `SS:[BP-2]` | `BA 13`，读入 AX 后为 `13BAH` |
| 栈版释放局部空间后 | `SP`、`BP` | `SP=0100H`、`BP=0000H` |

## 五、十进制结果输出

`INT 21H` 的字符输出功能接收 ASCII 字符，因此先将数值反复除以10，保存每次的余数，再逆序输出。

| 当前数值 | 除以10的商 | 余数 |
| --- | --- | --- |
| 5050 | 505 | 0 |
| 505 | 50 | 5 |
| 50 | 5 | 0 |
| 5 | 0 | 5 |

余数按个位到最高位产生。依次压栈后，再弹出就得到 `5、0、5、0`；每个数位加上字符 `'0'`，由 `AH=02H`、`DL=字符` 的 `INT 21H` 调用输出。

```asm
MOV BX,10
XOR CX,CX
PD_DIVIDE:
    XOR DX,DX
    DIV BX
    PUSH DX
    INC CX
    OR AX,AX
    JNZ PD_DIVIDE
PD_WRITE:
    POP DX
    ADD DL,'0'
    MOV AH,02H
    INT 21H
    LOOP PD_WRITE
```

`DIV BX` 对 `DX:AX` 组成的32位无符号数进行除法，商进入 AX，余数进入 DX。每次先清零 DX，使被除数对应 AX 中的16位数值。子程序至少执行一次除法，输入数值为零时也能输出一个 `0`。

## 六、输入1～100并求和

### 1. INT 21H 功能调用

| AH | 功能 | 参数与返回 |
| --- | --- | --- |
| `09H` | 输出字符串 | DS:DX 指向 `$` 结束的字符串 |
| `0AH` | 缓冲键盘输入 | DS:DX 指向输入缓冲区，按回车结束输入 |
| `02H` | 输出字符 | DL 为待输出的 ASCII 字符 |
| `4CH` | 结束程序 | AL 为返回码，本程序返回0 |

读取函数采用 `AH=0AH`，缓冲区结构为：

```asm
INPUT DB 80,0,80 DUP (0)
```

第一个字节是缓冲区容量，第二个字节返回实际输入字符数，不包括回车，字符数据从第三个字节开始。程序先检查字符数为1～3，再逐个检查字符是否属于 `'0'～'9'`。

### 2. 字符串转换与范围检查

设当前数值为 V，新读入数位为 d，按 `V=10×V+d` 累加。由于最多读取3个数位，解析范围最多为0～999，16位乘加不会溢出。解析完成后检查 `1≤V≤100`。

`1`、`01`、`001` 都表示上限1；空行、0、101、负数、带符号或空格的输入均提示错误并重新读取。错误分支在数位输出之前，不会留下未弹出的余数或局部栈空间。

### 3. 使用输入值作为循环次数

```asm
MOV N,AX
MOV CX,AX
MOV BX,1
XOR AX,AX
SUM_LOOP:
    ADD AX,BX
    INC BX
    LOOP SUM_LOOP
MOV RESULT,AX
```

本段执行前已保证 CX 在1～100之间。8086 的 LOOP 先将 CX 减1再判断是否为零，因此范围检查同时避免了 CX 初值为零时产生的计数回绕。

输出提示字符串时，AH 会被设置为09H，因此先将累计值保存到 RESULT，提示完成后再读回 AX，用十进制子程序输出。

输入100的运行结果：

```text
Please input n (1-100):
100

The sum:
5050
```

输入10时输出55，输入1时输出1。非法输入后的重试记录见 [B004.txt](output/B004.txt) 和 [RETRY.txt](output/RETRY.txt)。

## 七、C 实现与反汇编

```c
#include <stdio.h>

int main(void)
{
    unsigned int i;
    unsigned int total = 0;

    for (i = 1; i <= 100; ++i) {
        total += i;
    }
    printf("%u\n", total);
    return 0;
}
```

使用8086 DOS 目标编译，关闭优化。`main_` 的反汇编代码为70字节，共32条指令。其中 `[BP-02]` 对应 total，`[BP-04]` 对应 i，`CMP/JA` 对应循环条件，`ADD` 对应累加，`INC` 对应自增。

`printf` 调用前先压入结果和格式串偏移，调用后由 `ADD SP,4` 回收参数。`%u` 将16位无符号数值转换为十进制文本。完整的机器码、偏移和逐条注释见 [C反汇编_逐行注释.md](C反汇编_逐行注释.md)，对应原始记录见 [C.DBG](logs/C.DBG) 和 [S3C_DIS.TXT](logs/S3C_DIS.TXT)。

## 九、编译与复现

在 DOSBox 的源码目录中执行 `S3BUILD`，可汇编链接四份 ASM。必须将 `S3IO.INC` 与四份源码放在同一目录。

```text
masm S3REG.ASM,S3REG.OBJ,S3REG.LST;
link S3REG.OBJ,S3REG.EXE,S3REG.MAP;
```

其余汇编程序分别把文件名改为 S3DATA、S3STACK、S3INPUT。四份汇编程序使用相同工具链，文件名均符合 DOS 的8.3命名规则。

C 编译在 Windows 中使用 Open Watcom C16：

```text
wcl -0 -ms -bt=dos -l=dos -od -d2 -s -w=4 -we -fe=S3C.EXE -fo=S3C.OBJ -fm=S3C.MAP S3C.C
wdis -s=S3C.C -l=S3C_DIS.TXT S3C.OBJ
```

编译前应设置 WATCOM 为工具安装目录、INCLUDE 为其 h 子目录，并将 binnt 加入 Windows PATH。也可在仓库根目录运行 [验证脚本](tests/verify.py)，脚本会设置子进程环境、重新生成五份 EXE，并在单独的 DOSBox 进程中执行测试：

```text
python homework3/tests/verify.py --course-root D:\Homework\6\HUI
```

## 十、实验结论

求和循环在每轮加入当前加数后推进到下一数，经过100轮得到5050。累计值可以保存在寄存器、数据段或栈中，三种方式的差别主要体现在寻址和空间管理：寄存器版直接操作 AX，数据段版通过 DS 访问 RESULT，栈版通过 BP 和 SS 定位局部变量并在结束时恢复栈帧。

输入与输出均需要在字符和数值之间转换。输入按十进制位权累加，输出通过除10取余和栈逆序完成；C 版本中的循环和局部变量也对应到明确的16位指令及栈内位置。
